Intel HEVC decoder identification - optional Microsoft MFTrace diagnostic

This uses the same standalone synthetic HEVC test, not the live client.
Start Run-Intel-HEVC-Trace.cmd NORMALLY under the account where playback worked.
Do not run this first launcher as another administrator. Store codec availability
can differ between Windows accounts. Only MFTrace needs elevation, not the test.
The launcher uses Windows CMD and built-in native tools, without PowerShell.
It does not change or override execution policy. If organizational policy also
blocks CMD or the diagnostic executable, ask your administrator to authorize
the Microsoft diagnostic; this launcher does not bypass those restrictions.

On its first run, the helper downloads a 21 MB original Microsoft Windows SDK
CAB from download.visualstudio.microsoft.com. It extracts only the x64
mftrace.exe and mfdetours.dll into the local mftrace-tools folder. Both files
and the CAB have pinned SHA-256 hashes. No SDK or codec is installed. Later
runs reuse those local tools. Microsoft's SDK license applies to these tools:
https://aka.ms/WinSDKLicense

Close the live client. The test starts and waits BEFORE codec discovery:
1. It prints its PID and the path to Attach-Intel-HEVC-Trace-as-admin.cmd.
2. Open that result folder in Explorer. Right-click the ATTACH helper and
   choose Run as administrator. A different administrator account is OK here;
   the already-running test keeps its original ordinary-user account.
3. Wait until the Microsoft MFTrace console says it attached to the process.
   Return to the ORIGINAL test console and press Enter to start the trials.
4. Leave the synthetic video windows open. When the test is done, stop MFTrace
   with Ctrl+C if it is still running. Then return to the original console and
   press a key to package the logs.

No PowerShell script, unsigned-script exception or policy override is used.
No Parsec settings, account, host or network stream is used. Internet access
is needed only to obtain Microsoft's tracing tools on the first run.
The trace can contain local file paths. It is restricted to the launched
test and its children; the helper never attaches to another running app.

Send the generated intel-hevc-trace-....zip. It contains the MFTrace log,
console, the original JSON GPU report and the probe's SHA-256 identity.
Each run uses a fresh folder, so a failed run cannot package an old report.
The test itself has bounded playback trials. If MFTrace stalls, close its
console and keep the incomplete result folder; an incomplete run is not a pass.

What we inspect:
- The instantiated decoder CLSID/module and the resolved media topology.
- Whether that decoder actually processed HEVC input and produced output.
- D3D-manager / DXVA negotiation, failures and any fallback, correlated with
  the report's process-and-adapter-scoped GPU VideoDecode activity.

A Microsoft HEVC decoder can use hardware or software. Its name alone does
not prove either. Successfully passing a D3D manager, a GPU output texture,
3D activity, and an absence of decode counters are also insufficient proof.
If MFTrace does not expose acceleration execution, the result stays unknown;
an additional GPU ETW capture may be necessary. Trace overhead means this is
not a latency or copy-count benchmark. Do not integrate a CPU fallback into
the live client based on this diagnostic.

Tool payload extraction, hashes and Microsoft signatures have been checked.
The earlier elevated Intel trace captured codec-not-found under a different
administrator account; it did not measure the successful ordinary-user path.
This revised attachment flow needs a new laptop trace before any hardware
conclusion. Tracing the test is optional and does not change the live client.
